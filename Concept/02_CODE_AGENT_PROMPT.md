You are a senior full-stack TypeScript developer, real-time graphics engineer, UX designer, and test engineer. Build **the complete, production-quality SpectraStage application** described in `01_KONZEPT.md`. This is a delivery task, not a design brainstorm or proof of concept. ## Operating rules
1. Read `01_KONZEPT.md` in full. Treat it as the product specification and this prompt as the implementation contract. If requirements conflict, prioritize safety and functional acceptance criteria; document the resolution in `DECISIONS.md`.
2. Generate complete runnable code in the repository, with real dependencies, actual renderer implementations, functional interactions, and tests. Do not stub any core feature or replace all animations with videos/static screenshots.
3. Use English for all code, comments, UI copy by default, CLI commands, config, filenames, logs, docs generated by the agent, and tests. Design the UI so translations can be added later. User-facing labels can optionally support German localization.
4. Make safe, pragmatic decisions independently; do not pause to ask questions unless blocked by an external secret or a device-specific unknown. Record any assumption.
5. No external paid APIs, third-party accounts or CDN dependencies. The app IS hosted on the user’s public web server over HTTPS/WSS. Displays cache runtime assets and continue their current animation during brief internet outages; remote control requires connectivity.
6. Do not silently rely on microphone permission, online speech recognition, automatic audio playback, autoplay policies, or cross-origin exceptions.
7. The show must be child-friendly. Absolutely no jump scares, gore, aggressive flashing, strobe, or camera tracking. Lightning is a slow soft glow, never a rapid full-screen flash.

### E. Projector calibration
- Render test grid, guides, boundaries, safe area and reference markers on each output.

- Save per-display profiles in SQLite, export/import JSON, restore/reset calibration and live preview. Make sure UI-side coordinate transforms map correctly to projected coordinates.
- Warn that clipping/black images do not mean the light source stops emitting light.

### F. Security, reliability and safety

9. Mic permission is optional; audio rule works with synthetic test samples even without a microphone.
10. Unsupported browser speech API does not break controller.

12. Blackout reliably causes black render output and is accompanied by a hardware-safety warning, with deliberate resume.
13. Automated checks cover mathematical transform, auth, event protocol, scene lifecycle, show scheduler, noise gate, disconnected-client behavior and selected browser workflows.
14. At least 30 minutes of simulated playback with repeated scene switching does not show sustained unbounded memory growth or serious console errors; document extended burn-in steps for a 4-hour physical test.

## MANDATORY V2 OVERRIDES (read before coding)
Treat section 10 of `01_KONZEPT.md` as the controlling specification if any older text above sounds local-only, account-based or LAN-only. **Product name: SpectraStage**; all features in the older document still apply unless inconsistent with no-login multi-session hosted operation.

### Non-negotiable journeys
- Phone visits public HTTPS URL -> `Create Show` -> server generates a secure owner capability and an **8-character human-readable temporary device pairing code**. No registration or login. Show owner retains control with locally held token and optional explicitly exported recovery secret. Never share that secret via display pairing code.
- PC 1 visits `/display`, enters code and `Garage`; PC 2 visits `/display`, enters code and `Driveway`; PC 3+ same. Controller reviews and approves each join. Controller dynamically lists all approved devices; rename and assign roles/surfaces; targeted or grouped controls. Devices can reside behind separate NATs and connect outbound to the same WSS host.
- Two independent customers can create shows concurrently; each sees ONLY their own devices and scenes. Token-bearing endpoints must enforce session scope on REST, WebSocket subscribe and publish.
- An unknown device cannot seize an existing show merely by guessing/obtaining its code. Do not create publicly guessable admin URLs. Pairing code is short-lived and rate-limited; no capabilities beyond a pending join request.
- Optional controller sharing is explicitly invited/approved, separate from device pairing. Owner can revoke devices/invites, rotate pairing codes and delete session.

### Exact reliability semantics
- Heartbeat/pong liveness, reconnect backoff with jitter, authenticate on every connection, state snapshot after reconnect, increasing state revision, command IDs, ACK/NACK, bounded deduplication and transient event TTLs.
- Persist scenes, calibration, device assignments, blackout and playlists transactionally. Keep last animation running on projector PCs while WSS is unavailable. Cache initial resources with a service worker; version caches safely. Never claim a fresh page load works with an empty cache and no internet.
- Offline admin controls must be clearly disabled or explicitly queued with limited conflict-safe semantics (prefer disable), never claim that a command reached a disconnected projector. One-shot effects missed during downtime MUST NOT be fired late.
- Model failure scenarios: Wi-Fi disconnected for 30 s and 5 min, server container restart, network flapping, duplicate command resend, out-of-order snapshots, revoked pairing token, owner on a different phone. Reconnected displays converge to latest authorized state.
- Software blackout is not an emergency optical safety control. If network fails, it may not reach the projector; document local hardware shutdown.

### Mandatory code quality and deployment
- Node.js LTS >= 22, TypeScript `strict: true` everywhere, Fastify, WebSocket, React, Vite, Three.js + canvas renderer, SQLite, Zod, Vitest and Playwright.
- Production Dockerfile multi-stage, Docker Compose (mandatory, not optional), persistent named volume, non-root image, health endpoint and Compose health check, `.env.example`, `.dockerignore`, restart policy and graceful shutdown. Document reverse proxy deployment with Nginx/Caddy and WSS Upgrade forwarding, idle timeout settings, cert/HTTPS, PUBLIC_URL and TRUST_PROXY.
- Build and serve full bundle and graphics assets from own server (no CDN runtime). The service is designed for public hosting, **not limited to local WLAN**. Provide a realistic threat model for anonymous capabilities, rate limiting, brute-force, token leakage/recovery, cross-session isolation, and abuse protection.
- Extend acceptance tests: create session anonymously; pair/approve three displays; concurrently isolate two shows; disallow pair code as admin credential; disconnect/reconnect WSS while renderer keeps playing; server restart with persisted state; expired effects do not replay; Docker build and `docker compose up --build -d` are documented and validate where execution environment allows.
- Update every legacy mention of admin login, local-only operation or optional Docker in generated UI and docs. No inactive buttons or placeholders.
